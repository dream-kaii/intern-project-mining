# 复现练习（Stage 3B，可选）

目标：把选中的需求「从零再实现一遍」，让用户真正掌握需求背景与实现细节，简历和面试才经得起追问。

## 进入方式

Stage 3 结束时主动询问：「是否需要针对这个需求做一次复现练习？」用户同意后进入本阶段；后续也可随时要求「开始复现练习」。若项目不完整或无法本地运行，先说明限制，再决定是否继续（可做代码级复现）。

## 第一步：设计练习包（输出给用户）

练习包写到项目根目录 `PRACTICE_LAB.md`（若用户不想污染 git 工作区，可改写到项目目录外的备份目录旁；文件名用 `<需求名>-practice-lab.md`）。内容不含原始代码，可放心保留。练习包包含：

1. **需求背景**：为什么做、业务价值、现状痛点（来自 Stage 2 输出）
2. **需求规格**：输入、输出、主要流程、边界与异常情况
3. **验收标准**：可逐条勾选的清单（含可量化指标，如「重复请求只退款一次」「列表接口 N+1 消除」「编译通过」「与备份 diff 无无关改动」）
4. **涉及文件清单**：要改哪些文件、保留哪些（见下方「保留 vs 移除」边界）
5. **复现步骤建议**：推荐的实现顺序与自查点
6. **学习要点**：这个需求想练的技术点（幂等、缓存、N+1、事务等）与常见坑

## 第二步：备份（先备份，后移除；顺序不可颠倒）

- 把要移除的文件/代码段完整复制到**项目目录外**的备份目录，例如 `~/.codex/intern-project-mining-backups/<项目名>/<需求名>/`，保留原目录结构。
- 备份完成后做**完整性校验**：对备份与原始文件计算哈希（如 `Get-FileHash` / `sha256sum`）并逐项对比，把校验结果写进输出，确保备份与原始逐字节一致。
- 若项目是 git 仓库：先检查工作区是否有未提交改动；提示用户先 `git status` 确认、建议新建分支或先 commit 保护现场。skill 不主动执行 git 变更，避免覆盖用户未提交的工作。
- 向用户明确输出：备份路径 + 恢复方式 + 恢复后应达状态（把备份文件复制回原位后，编译与运行行为应与移除前一致，可用哈希对比验证）。

## 第三步：移除原实现（只移除实现，保留骨架）

**各层「保留 vs 移除」边界（以 Java 后端为例）：**

| 层 | 保留 | 移除 |
| --- | --- | --- |
| Controller | 类、类上注解、其余端点 | 该需求相关端点及其方法体（示例：删除 `refund` 端点，保留 `getByOrderNo`/`list`） |
| Service 接口 | 接口与该方法签名（是需求规格的一部分） | 无 |
| Service 实现 | 类、其余方法 | 该需求方法的方法体；保留方法签名，方法内留 `TODO(复现练习)` 并抛 `UnsupportedOperationException` 或返回占位 |
| Mapper/DAO | 类、其余方法的 SQL | 该需求相关的 SQL 注解/XML 映射；方法签名可保留也可删除，按「练习难度」决定（见下方中间态说明） |
| 模型/实体/配置 | 全部保留 | 无 |
| 已有测试 | 全部保留（可当作规格参考） | 无 |
| 无关代码 | 全部保留 | 无 |

- 移除范围仅限该需求的实现，一次只做一个需求，不要动无关代码。
- 在移除处留下 `TODO(复现练习): 见练习包 PRACTICE_LAB.md` 注释。
- **中间态说明**：移除后项目应保持**可编译**（如有构建工具，用 `mvn compile` / `go build` 等验证）；运行该需求相关功能会失败属**预期**（实现尚未完成）。若保留 Mapper 方法签名但删了 SQL，MyBatis 运行期会报 `Invalid bound statement`，这也是预期中间态，完成复现（补回 SQL）后消失——在练习包中明确告知用户，避免误判为环境问题。

## 第四步：用户独立复现

- 用户按练习包自己实现；skill 只做引导与答疑，不直接给出完整答案。
- 用户卡住时，skill 可给提示（定位到相关文件/接口、提醒看保留的测试或备份），不要直接粘贴原实现。
- 记录用户实现与原始实现的差异，供复盘。

## 第五步：复盘对比

- 用户完成后，对照备份 diff 差异。
- 逐条过验收标准，未达标项给出补齐动作。
- 分析差异原因：哪些是风格差异，哪些是更优/更差的取舍，为什么原始实现这么写。
- 引导用户把「复现过程中的难点与收获」补充到 Stage 4 简历素材和 Stage 5 面试预案。

## 安全与保密

- 先备份后移除；备份用哈希校验完整性；恢复路径与恢复后应达状态明确写在输出里。
- 备份目录含公司代码，同样遵守保密原则，不传外部。
- 任何一步用户可喊停：中止后至少保证备份完整、原实现可恢复。
