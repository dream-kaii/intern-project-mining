# 简历定制写法（Stage 4）

## 第一步：收集偏好（一次 1–2 个问题）

- 目标岗位：如后端开发（Java/Go）、全栈、特定方向
- 篇幅：一页 / 一页半
- 风格：技术向（重量化与术语）/ 平衡向 / 业务向（讲故事）
- 是否量化：需要量化（默认）/ 不量化
- 板块需求：实习经历、项目经历、技能清单、其他
- 有无已有简历草稿需要套用格式

## 第二步：模板/写法选择（给用户选）

- **模板 A「技术亮点型」**：以量化指标和硬技能开头，适合大厂/后端岗
- **模板 B「业务故事型」**：以需求背景和业务价值开头，适合业务型/中小厂
- **模板 C「项目深度型」**：以单个完整链路项目为主体，深挖细节

## 第三步：正常实习经历写法（固定四块内容）

1. **项目介绍**：项目做什么、给谁用、解决什么问题、规模与技术栈（2–4 句，可复用 Stage 1 画像的一句话定位 + 业务背景）。
2. **职责描述**：实习期间的角色与职责范围。
   - 用户不清楚时给三个选项：AI 代写 / AI 扩写 / 跳过这条
3. **工作内容**：做了什么，按 STAR 组织，每条含「需求背景 + 解决方案 + 量化数据」。
4. **量化数据与口径**：每个量化数字必须配套「数据来源与测量方法」说明，格式示例：
   - `查询耗时下降 50%` → 口径：JMeter 压测，同一接口改造前后各跑 5 分钟、并发 50，取 p95 对比；统计周期与基线写清楚
   - `缓存命中率 90%` → 口径：Redis INFO 命中统计，观察 24 小时；或应用侧打印命中日志统计
   - `SQL 耗时 2s → 200ms` → 口径：explain 前后执行计划对比 + 实际执行耗时采样
   - 还没实测的用「计划口径」标注，拿到数据后回填

## 通用规则

- 输出同时给：完整版、一句话口头版、多岗位侧重备选。
- 量化结果注明口径：实测 / 计划，并附测量方法说明（面试问「数据怎么来的」时直接复用）。
- 产出条数与难度要和实习月数匹配（3 个月写 1–2 条核心、6 个月 2–3 条），按 `references/intern-requirement-patterns.md` 分级，不堆砌不夸大。
- 所有不确定字段先问；用户答不上来就标「待确认」，不虚构。
