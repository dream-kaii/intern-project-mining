# 实习生典型需求分级（Stage 2 校准用）

目标：让挖掘出的机会「符合实习生真实工作量与能力」——宁可小而扎实，不可大而空；面试官深挖时不露馅。

## 按实习时长校准数量与难度

Stage 0 必须问清实习时长（已结束的，问实际实习了几个月）：

| 实习时长 | 建议简历产出条数 | 建议级别 |
| --- | --- | --- |
| 2 个月以内 | 1 条核心 + 若干小项 | 只做 L1 |
| 3–4 个月 | 1–2 条核心 | L1 为主，可带 1 条 L2 |
| 6 个月及以上 | 2–3 条核心 | L1 + L2 |

## 需求分级

### L1 实习生友好（简历核心，优先在项目中找这类）
1. **独立开发小型业务模块**：日志、字典、报表、文件上传等。工作内容：设计表结构 → DAO/Service/Controller → 参数校验 → 联调自测。
   - 简历口径：独立完成 XX 功能模块后端接口开发（CRUD、参数校验、联调交付）
2. **接口新增/改造**：增加查询条件、分页、排序、多表关联查询。含金量在「读懂原有业务逻辑、不破坏旧功能」。
3. **给已有查询接口加缓存**：Redis set/get + 缓存 key 设计 + 过期/刷新策略；不做整体缓存架构。
4. **SQL 优化**：定位慢查询、加索引、改写多表 SQL、explain 前后对比。
5. **MQ 生产者/消费者**：在现有异步场景发消息/消费消息（如通知、日志异步落库）；不设计 MQ 整体架构。
6. **定时任务**：Spring Task / XXL-Job 定时统计、同步第三方数据。
7. **通用工具类封装**：统一返回体、脱敏工具、导出 Excel。
8. **Java Agent/探针 demo**：采集方法耗时、打印调用日志、性能统计对接项目。
9. **补单元测试**：覆盖关键分支。

### L2 进阶（6 个月以上或想冲刺高难度面试才选）
布隆过滤器/去重组件改造、数据权限实现、网关限流、消息重试/死信、线程池统一治理、监控大盘接入。

### L3 高级（默认不做，仅理解）
整体缓存架构设计、分布式事务方案、MQ 整体架构、网关重构、核心支付/资金链路改造。

## 适配性检查（每条机会输出前自检，任一不过就排除或拆小）

- **工作量**：这条产出是否符合实习月数的真实工作量？（3 个月写出 5 个大模块 = 一眼假）
- **能力边界**：是否明显超出「写 CRUD + 调参 + 查日志」的实习生能力？（设计整套缓存架构 = 一眼假）
- **权责边界**：是否需要动核心资金/支付/生产高危链路？需要则排除或降级
- **细节可讲**：面试官深挖时，实习生能否讲出自己写的每一行、踩过的坑、查过的日志，以及量化数据是怎么测出来的？
