# 面试预案与熟悉计划（Stage 5）

目标：让用户真实掌握所选需求的背景与实现，确保简历上的每句话都经得起追问，并能从项目经历自然延伸到八股文考点。

## 熟悉计划清单（逐项给出具体做法）

- **复现练习（首选）**：针对简历上的需求做一次从零实现，见 `references/practice-lab.md`；这是建立真实掌握最快的方式
- **跑通端到端**：本地启动项目，真实走一遍该需求的完整链路（请求 → 服务 → 数据 → 返回）
- **读关键代码**：列出该需求涉及的核心类、方法、配置文件，能逐行讲清
- **画图**：画一张需求时序图 + 一张模块架构图，能独立复述
- **写理解文档**：用自己的话写一篇「需求背景 + 方案 + 为什么这么设计」的文档
- **讲一遍**：能给同事讲、或录音自查，讲清楚每个环节
- **看日志与监控**：真实查过日志、看过监控大盘，能说出正常与异常分别长什么样

## 面试追问 Q&A 框架

对简历上的每一条经历，准备以下问题的回答框架：

1. 为什么做这个需求？（业务背景与价值）
2. 你具体负责哪部分？（职责边界）
3. 技术方案为什么这么选？（选型与取舍、对比过什么方案）
4. 遇到的最大难点/坑是什么？怎么解决的？
5. 数据从哪来？指标怎么统计？（数据口径，最容易被问穿）
6. 如果重来/让你优化，你会怎么做？（改进方向）
7. 上下游怎么协作？（接口对接、联调、上线流程）

输出时每题给「参考回答框架 + 用户需要自己补齐的事实」，并标注必须亲手确认的细节。

### 量化数据问答（重点）
简历里出现的每个数字，都要提前写好「数据来源说明」并准备被追问：用什么工具测的（JMeter/压测/日志统计/explain 对比/Redis INFO）、统计周期、对比基线、当时的环境与并发量；答不上来的数字不要写进简历，写了的必须能解释。

## 项目 → 八股文延伸（重点）

目标：面试时从自己的项目经历自然过渡到经典考点，讲出「有实践 + 懂原理」。

讲法模板（按这个顺序组织）：
1. **具体场景**：项目里我遇到了 X（如退款重复、列表慢、缓存没生效）
2. **引出原理**：这背后涉及 Y（如幂等、索引、缓存一致性）
3. **讲原理要点**：Y 的核心概念与常见方案（2–3 句，可延展）
4. **我的方案与取舍**：当时怎么选、对比过什么、踩过什么坑
5. **改进方向**：如果重来/让你优化，怎么做

每个简历条目至少准备 2–3 个可延伸的八股文主题（直接复用 Stage 2 每个机会输出的「面试延伸」字段）。

高频主题参考（按项目实际情况挑选）：缓存穿透/击穿/雪崩与一致性、Redis 数据结构与持久化、MySQL 索引与 explain、事务隔离级别与 MVCC、锁与死锁、消息可靠性/顺序/幂等消费、分布式锁与分布式事务、线程池参数与拒绝策略、限流算法、JVM 内存与 GC、HTTP/TCP 基础。

注意：延伸的前提是项目里真实做过；先复现/跑通再讲，避免背题被追问穿。

## 反被看穿检查清单（真实掌握导向）

一深挖就露馅的典型细节，逐项检查并给出补齐动作：

- 没亲手配过环境 / 没本地跑起来 → 补：按 README 跑通一次
- 说不清数据结构与字段含义 → 补：读表结构并复述
- 没看过日志/监控 → 补：真实查一次，记录正常与异常样本
- 说不清接口入参出参和异常处理 → 补：逐个接口过一遍
- 讲不出需求为什么存在 → 补：问 leader/同事或读需求文档
- 量化数据对不上 → 补：确认数据来源与统计口径，写清楚
- 讲技术原理时和项目对不上 → 补：先复现练习，把原理和项目场景一一对应
- 简历产出与实习时长/能力不匹配（3 个月写 5 个大模块）→ 补：按 `references/intern-requirement-patterns.md` 分级删减到真实工作量

原则：不编造。所有写进简历的内容必须能通过上面的检查。
